# 04 · Notification function and email

**Assignment.** Backend owns recipient selection and function behavior. Use E1–E4 and architecture §2.1. Deliver an approval request to the eligible company approver and an order confirmation to the buyer who placed the order.

**Proposed delivery choice.** Use a local capture transport for development and deterministic load tests. Use Resend test delivery for the deployed smoke test, subject to sender/account eligibility. A capture transport can verify rendering and routing locally. A provider test address can demonstrate provider acceptance and simulated delivery outcomes. Neither proves delivery to a real buyer inbox. Confirm the sender setup and any external charge before enabling the integration. [Provider test addresses](https://resend.com/docs/dashboard/emails/send-test-emails) · [Idempotency keys](https://resend.com/docs/dashboard/emails/idempotency-keys)

**Evidence and decisions, 19 November 2026.** A3 observed one eligible company admin approve a synthetic cart and a separate final order response. The approval step can produce multiple types. For N1 select Admin-type approval, join its cart to its company and enumerate distinct admin employees with customer emails. Order confirmation uses the committed buyer address and order ID. The worker supplies the resolved recipient and an opaque recipient ID to the function. With two eligible admins, expect two delivery records. With none, record a routing failure for review. [Approval creation](../../../apps/backend/src/workflows/approval/steps/create-approvals.ts) · [A3 fixture](01-application.md)

**Receipt and replay.** Freeze the template version and inputs for each recipient. Use the same provider key and identical request on each attempt. Store a private intent before the send, then the accepted provider ID. Use generation-conditional receipt updates for concurrent deliveries. On replay, skip an accepted receipt. A timeout with no accepted receipt stays ambiguous. Retry inside the provider's 24-hour key window, then require reconciliation. Exercise simulated success and bounce at the provider's test addresses. Retain a redacted receipt and event timeline. The team owns sender verification and access for N4. Provider delivery remains untested. [Resend test delivery](https://resend.com/docs/dashboard/emails/send-test-emails) · [Resend key lifetime](https://resend.com/docs/dashboard/emails/idempotency-keys)
